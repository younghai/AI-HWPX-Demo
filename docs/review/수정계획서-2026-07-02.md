1. **Phase 0 → 1 → 2 → 3 순서 고정.** 로컬 사용자가 지금 겪는 무음 데이터 유실이 보안 하드닝보다 먼저다(현재 노출면은 127.0.0.1 뿐이므로).

3. Phase 0 완료 시점에 회귀 테스트(pytest + vitest + ESLint)를 함께 심어, 이후 Phase가 안전망 위에서 진행되게 한다.

## 리스크 및 의존성

- **rhwp 전 페이지 추출(2-2) 성능**: 대형 문서에서 WASM 렌더 비용 — 텍스트 전용 추출 API 유무 확인 필요, 없으면 서버측 XML 파싱으로 우회(Python이 이미 XML을 다루므로 저위험).
- **다크모드 정식 대응(0-5) 스코프 팽창**: 토큰 승격 중 시각 회귀 위험 — 화면별 스크린샷 비교로 통제, 여의치 않으면 `color-scheme: light` 고정 후 Phase 3로 이월.
- **초안 편집(2-1)은 상태 모델 변경**: draft 불변 가정이 깨짐 — `draftControllerRef` 취소 로직과 편집 중 재생성 충돌 케이스를 설계 단계에서 명세할 것.
- **인증 도입(1-1)과 로컬 UX 충돌**: `AUTH_MODE=local` 기본으로 로컬 무마찰 유지 — 배포 프로파일에서만 강제.
