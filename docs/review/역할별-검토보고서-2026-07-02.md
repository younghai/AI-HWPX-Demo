- **일자**: 2026-07-02
- **대상**: repo 전체 (client React 15파일, server Node 21파일, Python 파이프라인 12파일, shared 3파일, 스타일/문서)
- **방법**: ① 전 소스 정독 ② 실행 중인 앱에서 UI/UX 실측(다크모드 대비 수치, 모바일 뷰포트, 에러 플로우 클릭 테스트) ③ Python 경로는 `.venv` 런타임 실증(escape 파싱 실패, NFC/NFD 조회 실패 재현) ④ 시니어 백엔드/문서 파이프라인 리뷰어 2인 병렬 심층 리뷰

## 2. 시니어 디자이너 관점 (UI/UX) — 실측 기반

### P0급 — 온보딩 차단

**UX-01. 다크모드에서 설정 모달 판독 불가 (실측 확정)**
- 근거: `preview_inspect` 실측 — `.modal-content` 배경 `rgb(255,255,255)` + 텍스트 `rgb(232,232,232)` = **대비 1.2:1** (WCAG AA 기준 4.5:1). 스크린샷으로 "AI 연결 관리" 제목·프로바이더명이 거의 안 보임을 확인.
- 원인: `:root`는 `color-scheme: light dark` + 변수 스위칭을 선언했지만, `styles.css`에 `#fff`/라이트 rgba 하드코딩이 최소 8곳 — `.modal-content`, `.toast`, `.parsed-text-panel`, `.built-page`, `.empty-sample-card`, `.meta-grid > div`, `input/select/textarea`, `.login-overlay`.
- 영향: **macOS 다크모드 사용자는 첫 실행에서 API 키 설정 모달을 읽을 수 없음** → 온보딩 차단. 토스트(에러 메시지)도 동일.
- 수정안: 단기 — `color-scheme: light` 고정으로 다크 지원 철회(1줄). 정식 — 하드코딩 색을 `--surface`/`--surface-raised` 토큰으로 승격하고 다크 값 정의.

### P1

**UX-02. 정보 구조가 사용 순서와 반대**
- 좌측 패널이 "1. 생성 조건"(위) → "2. 원본 문서 업로드"(아래)인데, 실제 흐름과 EmptyState 안내는 "① 업로드 → ② AI 생성 → ③ 다운로드". 자기모순적 넘버링. 첫 사용자가 폼부터 채우다 업로드가 필수임을 뒤늦게 발견.
- 수정안: 업로더를 step 1로 최상단 이동, 파일 없을 때 생성 조건 패널을 시각적으로 후순위(디밍 or 접힘) 처리. 모바일(375px 실측)에서는 업로더가 긴 폼 아래로 밀려 첫 화면에 CTA가 안 보임 — 모바일 우선 배치 필수.

**UX-03. AI 연결 상태가 12px 점 하나**
- `TopBar.jsx:33-38` — "AI 미연결 - API 키 설정 필요"가 tooltip/aria-label에만 존재. 시각적으로는 빨간 점. 서비스 사용 가능 여부라는 결정적 상태가 hover 없이는 안 보임.
- 수정안: 미연결 시 텍스트 뱃지("AI 키 필요 — 설정하기" 클릭 가능) 노출. 연결 시에만 점+프로바이더명 축약.

**UX-04. 장시간 작업(AI 45s + 빌드 최대 60s)에 진행 피드백이 한 줄 텍스트뿐**
- 버튼 라벨 변경 + `parseStatus` 문장이 전부. 단계 표시·경과 시간·취소 수단 없음(AbortController는 코드에 있으나 UI 미노출).
- 보조 발견: 초안 미리보기의 단계 표시줄 `.preview-process-line`과 `.draft-section-meta`가 **CSS 미정의**(grep 확인) — 미스타일 인라인 텍스트로 렌더.
- 수정안: 4단계 스텝퍼(분석→AI 초안→HWPX 빌드→렌더) + 취소 버튼 + 예상 소요("보통 30–60초"). 누락 CSS 정의.

**UX-05. Optimistic draft가 '가짜 문장'을 생성**
- `helpers.js:16-43` — "원문 핵심 문장 "..."을 바탕으로 ... 정리합니다" 같은 진짜처럼 보이는 문장을 합성해 미리보기에 노출. '준비 중' 라벨은 있으나 본문이 실제 콘텐츠로 오인될 수 있음.
- 수정안: 스켈레톤(shimmer) UI로 교체. 문장 합성 제거.

**UX-06. 빌드 미리보기 5페이지 절단 무표시**
- `useRhwp.js:112` — `Math.min(pageCount, 5)`. 12페이지 문서면 5페이지만 보이는데 어디에도 표시 없음 → "미리보기=다운로드" 신뢰 원칙과 충돌.
- 수정안: "미리보기 5 / 전체 12페이지" 표시 + 더 보기(lazy render).

**UX-07. 20MB 초과 파일의 에러 경로 불투명** — FE-02와 동일 사안의 UX 면. 사전 검사 + 명확한 reject 메시지.

### P2

## 3. 시니어 PO 관점 (제품 / 서비스 프로세스)

### P1 — 핵심 가치 루프 결손

**PO-01. 초안 편집·부분 재생성 불가 (최대 갭)**
- 현재 루프: 업로드 → 전량 AI 생성 → (마음에 안 들면) 전량 재생성 → 다운로드. 문서 작업의 실제 루프인 "생성 → **검토·수정** → 확정"에서 수정이 없음. 섹션 단위 텍스트 편집, 섹션 단위 재생성, 목차 추가/삭제/순서 변경이 모두 불가.
- 영향: 실사용에서 "한 문장만 고치고 싶은데 전체 재생성(비용+시간+복불복)" — 도구 신뢰·리텐션 직결.

**PO-02. AI가 원문 전체를 보지 못함 (기대-실제 불일치)**
- `useRhwp.js:84-95` — AI에 전달되는 원문이 **처음 3페이지의 SVG 추출 텍스트**뿐. `extractTextFromSvg`(helpers.js:5-14)는 중복 라인을 전역 제거해 표 반복 헤더 등도 소실. 20페이지 사업계획서를 올려도 AI는 ~3페이지만 봄.
- 영향: "업로드한 문서 기반 생성"이라는 핵심 약속이 긴 문서에서 조용히 깨짐 → 품질 불만의 구조적 원인.
- 방향: rhwp 전 페이지 텍스트 추출(또는 서버측 HWPX XML 직접 파싱 — 이미 Python이 XML을 다룸) + 길이 상한은 요약/청크 전략으로.

**PO-03. `templateBodySlots` 죽은 기능**
- 서버 프롬프트는 템플릿 슬롯 수 맞춤 생성을 지원(`services/draft.js:9-11`)하는데 **클라이언트가 이 값을 아예 보내지 않음**(`useDraft.js:37-41`에 부재). v3에서 P1로 만든 기능이 v4 UI에서 미배선.

**PO-04. 문서 유형이 껍데기 분화**
- 5개 유형(보고서/제안서/회의록/공문서/기본)의 차이가 fallback 목차 5줄뿐. 회의록에 참석자·일시, 제안서에 수신 고객, 공문에 발신 기관 같은 유형별 필드·프롬프트·샘플 없음. 샘플도 공문서 1종뿐(5유형 대비).

**PO-05. 모델 전략 부재**
- 모델이 하드코딩(`claude-opus-4-7`, `gpt-4o`, `moonshot-v1-8k`, `grok-3-mini` — 구세대 포함)이고 UI에서 선택 불가. 단가표도 수기(`draft.js:109-114`), 비용 추정은 문자수/3 근사 — **두 API 모두 실제 usage 토큰을 응답에 주는데 버리고 있음**(`ai.js`가 text만 반환).
- 방향: 모델 선택 UI(품질/속도/비용 프리셋), 최신 모델 기본값, 실측 usage 기반 비용 표시.

**PO-06. Google 로그인이 가치 없는 마찰**
- 로그인해도 달라지는 것이 없음(문서 히스토리·개인 키 분리·설정 동기화 전무). 상단 최상 위치를 차지하는 버튼이 순수 마찰. 제거하거나(로컬 도구로서), 히스토리/키 소유와 묶어 가치를 부여하거나 — 결정 필요.

### P2

- **PO-07. 문서 히스토리 부재**: `generated/`에 파일이 쌓이는데 UI에서 과거 결과 접근 불가(브라우저 새로고침이면 유실). "최근 생성 문서" 목록은 저비용 고가치.
- **PO-08. HWP vs HWPX 모드 차이 인지 부족**: HWP 업로드 시 원본 양식이 보존되지 않고 기본 양식으로 새로 생성됨 — 업로더 캡션 한 줄로는 부족, 업로드 직후 모드 배너로 명시 필요.
- **PO-09. 성공 지표 부재**: 생성 성공률/재시도율/검증 경고율/소요시간의 로컬 기록조차 없음 — 개선 우선순위를 정할 데이터가 없다.
- **PO-10. 검증 결과의 사용자 언어화**: ValidationPanel이 `V11020` 같은 코드 중심 — "한컴에서 정상적으로 열립니다 ✓" 수준의 요약 우선, 상세는 접기.
- **PO-11. 브랜드 통일**(UX-10과 동일 사안의 제품 면) + **PO-12. 온보딩 부재**: 첫 실행 시 키 설정→샘플 체험을 잇는 가이드 플로우 없음(현재 EmptyState가 일부 커버 — 좋은 기반).
